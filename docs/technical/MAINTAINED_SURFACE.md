# Maintained Source Surface

This document is the remote-safe source boundary for MetaHuman architecture
checks, audits, and refactor planning. Its policy and owner descriptions were
last reconciled with the current worktree and validation entrypoints on
2026-08-31.

The executable policy below is authoritative. Both `scripts/check-architecture.ts` and `scripts/create-audit-inventory.ts` load this JSON block through `scripts/maintained-source-policy.ts`; they do not maintain separate path lists.

## Maintained Source Areas

- `packages/core`: engine and domain logic, storage abstractions, auth, policy, model routing, graph nodes, shared API handlers, and the work coordinator.
- `packages/agent-runtime`: shared finite-agent execution interfaces. Core owns
  admission and execution; this package does not load, register, or execute agents.
- `packages/cli`: the `mh` command interface. It dispatches to core or agent APIs instead of owning domain behavior.
- Native llama.cpp hosts text, vision, motion and embedding presets through one
  independent service per computer. `bin/llama-cpp-services` installs/starts the
  native unit; `providers/llama-cpp.ts` owns generation and embedding HTTP clients.
  Model Registry/Router own selected aliases and endpoints. There is no bundled
  Node inference process, secondary model manager or local-model management API.
- `apps/site`: Astro/Svelte interface and thin server transport for the web app.
  Its build entrypoint writes separate `apps/site/build/releases` artifacts and
  atomically selects the finished release through `apps/site/dist`. The existing
  launcher resolves the selected entry before starting Node. Running servers and
  compiled workers retain their release files across later builds; they are not
  rebuilt in place. The initial directory layout is preserved during conversion
  and requires an application restart. Retain old release files while a server
  or worker uses them; removal requires confirming those processes have ended.
- `apps/react-native`: maintained React Native interface shell and its bundled mobile runtime entrypoints.
- `brain/*`: workers, services, training, and the React Native bridge entrypoints above the engine. `brain/journal` and `brain/state` are runtime/history areas excluded by the policy.
- `external/kokoro` and `external/whisper`: tracked integration entrypoints maintained by this repository. Their virtual environments, downloaded dependencies, models, caches, and generated outputs are not maintained source.
- `etc`, `scripts`, `bin`, `docker`, `tests`, and remote-safe documentation and fixtures that describe or validate maintained behavior.
- Tracked interface assets such as icons and images are maintained when they are not generated or otherwise excluded by the policy.

## Critical Runtime Ownership Boundaries

These are the high-risk single-owner constraints that refactor work must preserve. They are not an inventory of every runtime component.

`start.sh` owns the application and its unfinished `bin/start-services` dispatch.
It starts the web application concurrently, cancels unfinished launch commands
on exit, and delegates service shutdown to `stop.sh --services-only`. `stop.sh`
dispatches to existing agent, model, voice, tunnel and event-bus owners; it does
not independently rewrite their registries or kill services by name. Core's
agent registry owns termination receipts and releases only the matching PID
registration. The existing event-bus server module owns its process, PID and
log for both shell and API callers. The Site authentication runtime connects
`llm-backend.ts` to committed, storage-ready session selection; default-profile
guessing is not a model startup path. See [startup instructions](../../STARTUP.md).

`AuthGate.svelte` owns the Site's login, registration/onboarding, password recovery,
guest profile selection and pre-authentication profile import views. Core owns
credentials, encrypted storage and sessions. The gate publishes verified users
and security policy through the existing client stores and clears previous profile
state on restoration or expiry. Normal login admits the app through that same
session check; optional sync admission failures use the existing action notice.
Both registration views share Core's registration route, and imported memories
complete through the finite Profile Sync agent before the existing reload.
`OnboardingWizard.svelte` owns committed progress navigation and finish/skip
requests. Its review step presents the parent's state and delegates completion;
Core's onboarding owner merges partial progress into existing user metadata.

Visual target acquisition and configuration use these same owners. The camera
worker owns detector prompts and generic track continuity; the Environment Bridge
carries finite visual-read/configuration requests and ordinary recognition
telemetry, including query and source-frame identities. The existing active-task
program admits acquire/search/select/release steps and stationary observation.
Acquisition retains its source image and returns candidates through the existing
continuation node to the configured task workflow, preserving the original
instruction admission. A final search/select/release configuration step or stationary visual behavior
returns its receipt or image assessment, query identity and perception through this
same planning continuation. A stationary observation returns positive, negative
or uncertain assessment evidence; a successful visual result is not a prerequisite
for that handoff, and returning an assessment does not complete the objective;
remaining programmed steps still execute before that handoff. It creates no
synthetic user turn, automatic candidate choice, or independent planner. The task selector decides the next program;
Goal Review continues to assess completion. A selected visual region always
refers to its retained image bytes. Track IDs estimate continuity and do not
establish personal or physical-object identity.

The active-task nodes' version 2.2 contract separates desired, pending and
acknowledged steering controls in the existing checkpoint. Steering v1 receipts
correlate to the original motion, command, revision and session; acceptance does
not establish physical movement. Failed, unsupported and uncertain outcomes
remain model-visible, and uncertainty must be reconciled before another update
or replacement motion. A capture receipt establishes only the capture step:
the correlated image goes through the existing model router/provider bridge in
an asynchronous Coordinator job with explicit remote placement. Positive target
and completion-criteria evidence requests Finish on the original gait. Only its
correlated terminal receipt advances the phase. Model-selected locomotion uses
`locomotionGoal` on the existing action contract. Active Task evaluates distance,
relative turn and approach endpoints; visual and follow endpoints reuse its
existing behavior evaluator. The gateway advertises locomotion separately from
finite robot commands and rejects bare gait starts on the Environment path;
manual/internal gait primitives retain their actuator owner. Neither settings
acknowledgment nor gait termination establishes endpoint success.

The owner-approved missing-measurement behavior returns incomplete before start,
or requests Finish on the original gait when required evidence disappears during
movement. Camera position, IMU orientation and selected-target evidence retain
independent availability, references and source times. Metric camera evidence
comes from the existing camera worker's calibrated ground-plane estimator;
selected ground points refer to exact Core-retained source images. It does not
infer object depth or ground contact from a detector box. Orientation transport
expiry reuses the gateway's existing four-second control freshness interval,
as explicitly approved; reading cached telemetry never renews it. Camera expiry
uses the existing camera freshness setting. Unknown physical outcomes retain
their existing reconciliation requirements.

Depth resource lifetime belongs to the existing Active Task and Body Control
camera owners. Metric navigation acquires/releases `depthDemand` through
`environment.visual.read`, independently of ordinary camera reads. The bridge
retains active consumer/execution/request identities for reconnect and terminal
execution cleanup; it does not scan execution history. Body Control shares depth
among navigation, recording of an active gait and explicit dashboard samples, and
unloads it after the last consumer releases. Streaming and photos remain separate.
Enabling gait logging or learning alone does not acquire depth; the recorder
uses the gateway's existing active-command state and trace-drain lifecycle.

The Coordinator's existing `notBefore` work owns source-expiry wakes, and
`environment.cancel-owned-work` checks execution ownership before using its
existing cancellation path. No node creates a private queue or inference timer.
Description-based motion uses `requestMotion` through that same command owner. Body Control’s configured motion system owns generation and execution; the adapter correlates the admitted action with the original Freestyle job and returns its results without regenerating on bridge reconnect. MetaHuman has no joint-generation workflow, trajectory decoder, or trajectory-training export. Its training bank curates Intent and Task decisions; Body Control owns Freestyle generation, motion training, and the manual demo library.
Heavy inference remains asynchronous. Ongoing visual behaviors use the existing
`active_task:<session>:perception` subscription; goal-bearing locomotion uses
its `:locomotion` suffix so orientation updates do not wake unrelated observers.
Perception and locomotion delivery share one outstanding sensor signal while
preserving the latest state and immutable prior evidence. Bridge telemetry and
state-only connection observations resolve the authenticated owner and deliver
to that profile's durable waits. Finishing a finite Coordinator job does not
remove the subscription. Existing node-version checks distinguish older
checkpoints; no old gait program is silently rewritten into a measured goal.
`robot-status-live.ts` reads sensing, recognition metrics, gateway command provenance,
Coordinator leases, correlated receipts and existing active behavior checkpoints at
context-read time. Robot Status and Environment Mode task/conversation consumers
reuse this projection; it stores no lifecycle state and admits no work. Frame expiry,
identity uncertainty and unavailable physical measurements remain explicit. Raw
images stay on the existing vision path. Body Control owns the analyzed JPEG/result
pair; its camera read places the matching recognition in frame metadata. Core's
`environment-interface/perception.ts` projects that metadata beside image content
for autonomy, Environment Mode and Robot Status. Active Operator dispatch and the
Robot Status queue handler preserve the delegated pair; the saved Status graph
connects the existing operator input and image input to its context builder.
Recognition metrics travel on the existing bridge telemetry route; they never
trigger an LLM call.
The shared [task-selection contract](../../packages/core/src/environment-interface/task-selection.ts)
belongs to Environment Interface: output schema, decision types, validation,
context/envelope construction, projections and planning delegation share that
owner. Graph nodes and training-evidence readers import it directly; the existing
Core and nodes export barrels preserve their public symbols. These utilities do
not register graph nodes.
Successive frames update the latest observation but coalesce behind one unconsumed
perception wake per execution. Historical event evidence and command receipts stay
unchanged; pending outbox delivery is retried even when the wake is coalesced.
A model-selected behavior steering on `person` uses the approved single-person
loss policy in that same checkpoint: a fresh zero/multiple-person observation
requests owned cancellation; its three-second observation-only window cannot
settle an unresolved command. Three distinct successive fresh frames spanning
one second identify only a candidate person. Explicit `single_person_resume`
operator events require the current candidate, correlated prior termination and
unchanged ownership; a new action identity is admitted. There is no automatic
resume or named-person association. Work Coordinator → Saved workflows exposes
candidate timestamps, the bounded observation window and prior command termination
from the existing task projection. Its owner-only Confirm candidate and resume
button posts to the existing execution endpoint. The Coordinator delivers one
idempotent `single_person_resume` event and schedules the existing graph resume;
HTTP acceptance means requested, not resumed. The active-task owner rechecks the
current frame, correlated termination and body ownership when consuming it.
No model-visible selection instruction is introduced. Existing
durable executable-version checks reject incompatible old checkpoints instead
of interpreting their pre-acknowledgement steering state as a fresh motion.

There is no Digest agent, separate preference-learning system, or persona cache execution path.
- Organizer is finite coordinator work: `brain/agents/organizer` selects bounded profile-resolved episodic records and executes `etc/cognitive-graphs/organizer-agent.json` once per record. Core memory scanning, validation, encryption, and atomic metadata persistence remain owned by `packages/core/src/memory.ts`; the graph must not scan or write profile files directly. Sleep Workflow owns automatic admission, while manual CLI, UI, and mobile adapters call the same agent contract.

The Brain dataset pipeline freezes messages and manifests. Training History exposes preparation, comparison, decisions, approval suspension and cleanup recovery. Personalization training workers do not advance a base-model registry, change roles, or write an active-adapter pointer. The manually triggered Environment Training Trainer exports owner-reviewed decisions, temporarily stops the existing 9B and shared 0.8B llama.cpp services plus the optional 2B service for GPU fit/evaluation and restores their prior running state, fits intent/task LoRAs, evaluates each candidate and the current adapter on the same frozen cases, and exports an adapter-only GGUF. ## Excluded and Local Areas

- `apps/code-oss` is legacy Studio/Code OSS bulk and `apps/mobile` is the deprecated Capacitor-era app. Neither belongs in normal MetaHuman architecture audits unless explicitly reopened.
- `vendor` contains upstream submodules or third-party source. Preserve it as a dependency, but do not treat it as a MetaHuman refactor target.
- Runtime profiles, persona data, memory, logs, outputs, state, caches, virtual environments, model weights, downloaded tools, generated builds, backups, and generated audit inventories are outside the maintained source surface.

  remote-safe pointers to it. These files belong in version control and are

  Machine-local agent and editor data remains outside the remote-safe contract.

## Remote Safety

Exclusion from architecture refactoring is not permission to track unsafe data. Remote-safety checks still inspect the complete tracked tree, including excluded areas.

Tracked remote content must not include personal profile data, private memories, local browser state, local audit scratchpads, tokens, model weights, generated logs, or local agent configuration. Use sanitized templates, fixtures, and examples when runtime shape must be documented.
