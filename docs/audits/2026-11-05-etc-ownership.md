# etc ownership and orphan review — 2026-11-05

Reviewed all 93 files present under `etc/`, including templates, local configuration, cognitive graphs and backup directories. This is a source/entrypoint review, not a claim that every configured capability was exercised live.

Configuration values, credentials, personal settings and backup payloads are omitted. Reader and writer columns distinguish the repository file from similarly named profile or mobile app-data files. Source files were already modified by other work; unrelated changes are preserved. Retention means an identified role, not certification of every stored setting.

## Findings and removal boundary

Removed four confirmed orphan files: `etc/config`, `etc/network.json`, `etc/boredom.json`, and `etc/boredom.json.template`. The environment file has no current source, startup or installed-systemd reader. The old desktop network file has no desktop reader or producer; React Native owns a different app-data file and WiFi-broadcast schema. Before removal, the boredom seed was only created/copied; no runtime consumed its interval settings.

Removed the old boredom creation/copy paths in the existing CLI/profile owners and the three obsolete root-file ignore entries. Legacy template copying now excludes the retired setting. Existing user-profile copies are outside this directory review and are preserved. Current Boredom Observer/Movement/Reflection work remains owned by Robot Operator, Agent Catalog and the Work Coordinator; its graph/configuration contracts are unchanged.

All built-in graphs remain supported: named modes resolve dynamically as `${mode}-mode.json`, explicit graph paths are supported, planner/reviewer filenames are selected from configuration, and the graph editor lists and saves the maintained directory. Literal filename search alone misses these consumers. The four backup files have real recovery/listing readers and are retained.
