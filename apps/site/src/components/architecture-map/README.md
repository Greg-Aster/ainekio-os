# System architecture map

Served at `/architecture` by the existing Ainekio OS Site Node.js server, inside its existing AuthGate. The cognitive workflow editor and executable graphs are unchanged.

One continuous Svelte Flow canvas uses nested, collapsible groups. All groups are expanded by default. A saved browser expansion state is restored when present; Expand all opens every group without resetting saved positions. The layout follows Human → Ainekio OS → Body Control → V2 body, with inference below. Ainekio OS is a software-ownership boundary, not a process or computer. It includes browser/CLI/Android entry points, the shared Core library, the agent system, stored state/configuration and training/evaluation tools. Reset layout restores these defaults. Expand reveals children in place; collapse represents their crossing connections at the group boundary. The built-in MiniMap at bottom right pans/zooms the same canvas. Dragged positions, expanded groups and viewport are saved in this browser. Coordinates from the previous hierarchy are replaced automatically on first load of the corrected layout. Restored or dragged positions are packed against the current sibling bounds, so expanding a group moves later siblings clear of its new size. Connections use the nearest card side and recompute after a drag; their original labels remain in connection details.

The Agent system group uses a compact vertical list with labeled sections for system infrastructure, finite agents, workflows and persistent services. Infrastructure uses unboxed rows; agent families, workflows and services have distinct row treatments and explicit type labels. Agent Catalog is labeled Registry, not an agent. Each row keeps its description, connection ports and selectable details; move the list by dragging its group. Saved card coordinates do not scatter the rows.

Boundary labels distinguish the software system, functional areas, the shared library and stored data. Dashed outlines with explicit runtime labels identify Node.js server/CLI processes, finite worker processes and persistent service processes. Agent coordination code remains library infrastructure; workflows are definitions/composition, not permanent service processes. The Android client has its own embedded HTTP server and shared Core adapter; it is not drawn as a desktop-server dependency.

Shapes distinguish roles: circle = person; window frame = interface; capsule = process; double border = execution/control owner; rectangle = library function; hexagon = service API; slanted box = hardware; notched tag = model. Collapsed groups use folder tabs, stacked sheets, chassis or service-rack outlines, while expanded groups identify their boundary type with distinct outlines and labels.

`architecture.json` owns this map's source-based documentation content, extending the robot diagram with the maintained interface, storage and training owners listed in supportingSourceDocuments. `canvas-model.ts` derives native parent/child nodes and aggregates boundary connections without losing the original labels or direction. The details panel preserves descriptions, sources and configured endpoints. This is a reference map, not a live runtime/status display.

The details panel's Read aloud button uses the existing shared TTS playback client and configured voice settings to read the selected item's title, description, details, sources and endpoints. It also reads selected connection details. Stop cancels the reading; changing selection or closing the panel releases its playback request.

Selecting a node highlights its connected lines and shows their data labels. The information panel lists the original connections, including those combined at a collapsed group boundary. Selecting a line focuses its data; clicking the canvas clears the selection and labels. These are documented data paths, not live execution events.

Highlighted lines, arrowheads, labels and panel entries share a color. Labels keep a readable text size as the canvas zoom changes. Click a line or its panel entry to animate its documented direction: one-way lines flow toward the arrow; two-way lines alternate directions. This animation does not indicate live traffic.

Run `pnpm test:architecture-map` from the repository root. Build/serve with existing Site commands; there is no separate architecture server.
